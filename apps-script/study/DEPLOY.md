# 部署成 Apps Script Web App

這個資料夾有三種頁面：

- **首頁** `…/exec`：網址沒有帶編號時，先問是受試者還是施測者。受試者輸入編號後進入自己的頁面；施測者輸入密碼後進入施測者頁。

- **受試者頁** `…/exec?p=P01`：每位受試者一條固定連結，每天打開同一條。程式依進度決定今天是第幾天。受試者每天選一個影片類別（脫口秀、美劇、歌詞），程式從他那組還沒學的字裡挑 2 個。學完紀錄會自動寫進試算表。
- **施測者頁** `…/exec?view=staff`：進度表、每天的訊息、預覽、資料。要輸入施測者密碼才看得到資料，不用 Google 帳號。

資料寫在試算表的兩個分頁：

- `Sessions`：每次學習一列。
- `Cards`：每張卡一列。

> **先做影片檢查：** 部署前，先照 [`../video-check/DEPLOY.md`](../video-check/DEPLOY.md) 在台灣和美國各測一次，確認 Apps Script 網址下影片能播。

## 檔案

| 檔案 | 在 Apps Script 編輯器裡的名稱 | 內容 |
| --- | --- | --- |
| `Code.gs` | `Code.gs` | 伺服器端：產生頁面、收紀錄、算進度、檢查施測者密碼 |
| `participant.html` | `participant` | 受試者頁 |
| `staff.html` | `staff` | 施測者頁 |
| `home.html` | `home` | 首頁：選身份 |
| `config.html` | `config` | **研究設定**：受試者名單、組別、序列、每組的 14 個字、聯絡人、回饋表單 |
| `cards.html` | `cards` | 43 張卡片的內容，由 `dev/build-cards.mjs` 從 prototype 產生 |
| `common.html` | `common` | 兩種頁面共用的程式 |
| `dev/` | 不用上傳 | 本機預覽和測試用 |

## 部署（約 20 分鐘，做一次）

### 1. 建立試算表和程式

1. 在 Google 雲端硬碟新增一份試算表，例如「Spec study data」。
2. 選單「擴充功能 → Apps Script」。
3. 把 `Code.gs` 的內容整份貼上，取代預設內容。
4. 左邊「檔案」旁點「＋ → HTML」，建立 `participant`、`staff`、`home`、`config`、`cards`、`common` 六個檔案。名稱都不要加 `.html`。
5. 把這個資料夾裡對應檔案的內容，整份貼進去。
6. 按儲存。

### 2. 填研究設定（`config`）

`/*CONFIG*/` 和 `/*END*/` 之間必須是合法的 JSON：用雙引號，最後一項後面不能有逗號。

- `contactName`、`contactHow`：受試者有問題時找誰、怎麼聯絡，例如 `"LINE：jay123"`。
- `feedbackFormUrl`：每日回饋表單的網址。
- `feedbackPrefill`（選填）：讓表單自動帶入編號和「Prototype」。
  1. 在 Google 表單點「⋮ → 取得預先填入的連結」。
  2. 隨便填一個編號，選好「Prototype」，按「取得連結」。
  3. 網址裡會有 `entry.123456=…`，把編號那一格的數字填進 `participantEntry`，把哪一段那一格的數字填進 `sessionEntry`。
- `participantUrl`：先留空，第 4 步部署後再填。
- `participants`、`words`：已經依目前的實驗設計填好了，要改再改。`words` 的順序就是同一類別裡挑字的順序。

### 3. 設定施測者密碼

1. 編輯器左邊「⚙ 專案設定 → 指令碼屬性 → 新增指令碼屬性」。
2. 名稱填 `STAFF_PASSWORD`，值填施測者密碼，例如一組不好猜的英數字。
3. 把密碼傳給團隊成員，不要傳給受試者。

說明：

- 密碼只存在這裡，不會出現在網頁原始碼裡。
- 要換密碼，直接改這個值就好，不用重新部署。
- 登入後同一個分頁 6 小時內不用再輸入。
- 10 分鐘內錯 10 次，會暫停 10 分鐘。

### 4. 部署（只要一次）

1. 「部署 → 新增部署作業」，類型選「網頁應用程式」，然後設定：
   - **執行身分：我**
   - **誰可以存取：任何人**（受試者和施測者都不用登入 Google）
2. 按「部署」並授權。如果出現「Google 尚未驗證這個應用程式」，點「進階 → 前往（不安全）」。
3. 複製網址（結尾是 `/exec`），貼到 `config` 的 `participantUrl`，然後儲存。
4. 「部署 → 管理部署作業 → ✎ 編輯 → 版本：新版本 → 部署」，讓剛填的網址生效。

部署完成後，同一個網址有三種用法：

| 網址 | 給誰 |
| --- | --- |
| `…/exec` | 首頁，選身份 |
| `…/exec?p=P01` | 受試者的個人連結 |
| `…/exec?view=staff` | 施測者頁（要密碼） |

> **找不到「任何人」：** 學校帳號可能只能給同校的人用。請改用個人 Gmail，從第 1 步重做。

### 5. 上線前測試

1. 打開首頁，選「我是施測者」並輸入密碼。施測者頁最上面不應該有紅色的「設定有錯」。黃色的「還沒填完」可以照著補。
2. 在施測者頁的「預覽」，選 X、Y 各試幾天，把整個流程走完。
3. 打開試算表，確認 `Sessions` 和 `Cards` 多了 `isTest = TRUE` 的列。
4. 測試的列可以留著，進度表和統計都不會算進去。

### 6. 發連結

- **第 1 天前：** 施測者頁「訊息 → 類型：第一次發連結」，每人一則，請受試者加到書籤。
- **每天早上：** 在受試者當地的早上，從「訊息 → 每天早上的提醒」複製傳送。「第幾天」和「先做哪一段」依每個人的進度自動產生。
- **每天晚上：** 看「進度」，「今天還沒做」的人要提醒。

## 清除資料

施測者頁「資料」區最下面的紅色框可以清除資料。常見的用法：

- 上線前，清掉自己試跑的 TEST 資料。
- 某位受試者要重來，清掉他的紀錄。
- 正式開始前，全部清空。

### 防呆措施

1. **先選範圍**：只清除測試資料（TEST）、某位受試者的全部紀錄，或全部資料。
2. **先看會刪多少**：按「清除…」後，會先列出要刪幾筆學習紀錄和卡片紀錄。如果包含正式紀錄，會用紅字提醒。
3. **輸入確認文字**：要輸入「刪除」，清除全部資料時要輸入「刪除全部」，「確定刪除」才能按。
4. **伺服器再檢查一次**：伺服器會檢查密碼通行碼和確認文字，兩個都對才刪。
5. **自動備份**：刪之前，會把 `Sessions` 和 `Cards` 整份複製成「備份 Sessions 日期時間」「備份 Cards 日期時間」兩個分頁。

### 誤刪時怎麼救回

1. 打開試算表的備份分頁。
2. 選取要救回的列（不含標題列），複製。
3. 貼到 `Sessions` 或 `Cards` 最後一列的下面。

備份分頁不會自動刪除。確定不需要之後，可以在試算表裡手動刪掉。

## 之後要改東西

- **改了程式或設定：** 儲存後要「管理部署作業 → 編輯 → 新版本」，不然網址還是舊版。
- **改了卡片內容**（在 `vocab-study-prototype.html` 改句子、字義、片段時間）：
  1. 在 repo 根目錄執行 `node apps-script/study/dev/build-cards.mjs`。
  2. 把新的 `cards.html` 貼進編輯器。
  3. 照上一點部署新版本。

## 規則（程式怎麼判斷）

- **第幾天**：依進度算，已完成幾天加 1。漏做一天的話內容會順延，不會跳過任何字。
- **一天只能做一次**：以受試者瀏覽器的當地日期為準。同一天再打開會顯示「今天已經完成了」。
  - 如果同一天還是送了第二筆（例如開了兩個分頁），會標成 `duplicate`，不算進度。
- **選類別、挑字**：
  - 受試者每天選一個影片類別，程式從他那組還沒學的字裡，依 `words` 的順序挑 2 個這個類別的字。
  - 這個類別只剩 1 個字時，就再從剩最多字的類別補 1 個。
  - 學完的類別不能再選。
  - 選了哪一類記在 `Sessions` 的 `chosenCategory`。
- **檢查送來的字**：如果送來的字不屬於這組，或已經學過，會標成 `card-mismatch`。
- **先做哪一段**：序列 A 在第 1、3、5、7 天先做 Prototype，序列 B 在第 2、4、6 天先做 Prototype。
- **送出失敗**：紀錄會先存在受試者的瀏覽器裡，下次打開同一條連結時自動補送。受試者也可以下載備份檔，或複製文字傳給團隊。
- **TEST 編號**：`?p=TEST&group=X&seq=A&day=3` 可以打開任何一天，資料標成測試。預覽時當作還沒學過任何字。

## 本機預覽（不用部署）

```bash
node apps-script/study/dev/server.mjs
```

打開下面的網址，後端會換成本機的模擬資料（存在瀏覽器的 localStorage）：

- 首頁：<http://localhost:8100/>
- 受試者頁：<http://localhost:8100/participant?p=P01>
- 施測者頁：<http://localhost:8100/staff>（本機密碼是 `test`）

一些測試用的方法：

- 網址加 `&fail=1` 可以模擬送出失敗。
- 在瀏覽器 console 執行 `MOCK_SHIFT_DAYS(1)`，會把所有紀錄的日期往前推一天，馬上就能試「明天」。
- `MOCK_RESET()` 會清空模擬資料。

要用 `localhost`，不要用 `127.0.0.1`，否則音樂影片會被擋。
